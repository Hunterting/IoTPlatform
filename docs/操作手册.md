## 1. 系统概述

智厨云平台是一个面向厨房场景的**多租户物联网（IoT）SaaS 平台**，用于设备的接入、实时监控、告警联动与运维工单管理。

- **多租户**：一套平台承载多个客户（租户），各租户数据按 `AppCode` 行级隔离，互不可见。
- **超级管理员**可跨租户管理全部客户；**租户内角色**仅能操作本租户数据。
- **设备接入**以安圣（AnSheng）系列 4G 设备为主（4G 四路开关、电表、水表等），通过 MQTT 协议上报数据，平台统一采集、存储与展示。

## 2. 角色与权限

### 2.1 角色

| 角色 | 说明 | 数据范围 |
|------|------|----------|
| 超级管理员 `super_admin` | 平台最高权限，跨租户管理 | 全部客户 / 全部设备 |
| 管理员 `admin` | 租户内管理，可管理用户、设备、配置 | 本租户 |
| 操作员 `operator` | 日常设备操作、控制下发 | 本租户（按区域/权限） |
| 客户管理员 `customer_admin` | 管理特定客户的数据，权限等同租户管理员 | 本租户 |
| 普通用户 `user` | 基础查看权限 | 本租户 |

### 2.2 权限模型（RBAC）

- 平台采用**基于权限点（Permission）的访问控制**：左侧菜单与各项功能按钮均绑定权限点。
- **超级管理员**：`hasPermission` 恒为 `true`，可见全部菜单（含未来新增项）。
- **其他角色**：仅当服务端下发的权限集合（`permissions`）包含对应权限点时，才显示对应菜单与可执行对应动作；无权限的菜单自动隐藏。
- 写类操作（如下发设备指令、修改配置）除菜单可见性外，按钮还会单独做"写权限"门控——只读用户可进入页面查看，但下发/编辑按钮为禁用态。

> 若某用户"看不到菜单"或"按钮是灰的"，通常是权限未授予，请联系超级管理员在「用户管理 → 角色管理」中为其角色追加相应权限。

## 3. 登录与导航

### 3.1 登录

1. 在浏览器打开平台地址，进入登录页（标题：**数智物联网厨房 SaaS 管理平台**）。
2. 输入**邮箱地址**与**密码**，点击「登录」。
3. 默认超级管理员演示账号：`admin@system.com` / `admin123`（仅用于初始/演示，生产请改用强口令账号）。
4. 登录失败提示：请检查邮箱/密码是否正确、网络是否可达。

> 登录页不会在用户未登录时主动请求业务接口；登录成功后才加载字典等基础数据。

### 3.2 选择租户（仅超级管理员）

- 超级管理员登录后进入**租户选择页**，需先选择一个客户（租户），再进入该租户的工作台。
- 租户内角色登录后由系统依据其 `AppCode` / `customerId` 自动定位到本租户，无需手动选择。

## 4. 核心操作流程

> 本节为日常主线：**认领设备 → 实时监控 → 告警 → 工单**。

### 4.1 设备认领 / 注册（AnSheng 设备）★

安圣系列设备需先"认领"才能成为平台可管理的 Device 并接入数据。

**操作步骤**

1. 进入 **设备管理 → 安圣设备**，点击「认领 / 新增设备」。
2. 填写 / 选择待认领设备的 **IMEI 或序列号**。
3. 系统自动**探测**设备（`getDevInfo` → `getDevStatus`），并**判定设备品类**（如"4G 四路开关""水表""电表"），绝不写死产品名。
4. 在认领表单中补充：
   - **设备名称**
   - **设备品类（Kind）**：如 4G 开关、水表、电表等
   - **所属项目（Project）**
   - **所属区域（Area）**
   - **能源类型（EnergyType）**
5. 提交后，平台完成"探测 → 判品类 → 建档 → 转 Device"，设备出现在**设备列表**并开始上报数据。

> 认领是"设备进入平台"的唯一入口；认领成功后无需再手动建设备。若提示 IMEI 已认领，说明该设备已存在。

### 4.2 实时数据监控 ★

| 入口 | 用途 | 说明 |
|------|------|------|
| **设备列表** | 查看本租户设备、在线状态、按区域过滤 | 主设备清单 |
| **安圣设备** | 安圣系列设备总览 | 4G 开关 / 水表 / 电表等的聚合视图 |
| **开关控制** | 4G 开关实时状态 + 下发控制 | 需 `SEND_DEVICE_COMMANDS` 写权限 |
| **电量统计** | 电表实时/统计数据 | 电压、电流、功率、电量 |
| **水流量** | 水表实时流量、累计流量、脉冲 + 流量配置 | 含 `k / offset / 量程` 配置 |
| **区域管理** | 按区域组织设备 | 支持区域过滤与授权 |

**水流量模块**（T12，镜像电量计范式）：
- 实时流量：瞬时流量 `iFlow`、累计流量 `tFlow`、累计脉冲 `tPulses`。
- 流量配置：`k`（系数）、`offset`（偏移）、`minFlow` / `maxFlow`（量程）。
- 操作：拉取实时流量（下发 `getFlowInfo`）、读取/设置/重置配置（对应 `getFlowConfig` / `setFlowConfig` / `resetFlowConfig`）。下发为异步，约 1.5 秒后自动补查镜像值。

### 4.3 告警中心 ★

1. 进入 **设备管理 → 告警中心**。
2. 查看告警列表：设备、告警级别、触发时间、内容。
3. 处理流程：
   - **确认**：标记告警已读/受理。
   - **派单**：将告警转为工单，指派处理人。
   - **关闭**：处置完成后关闭告警。

### 4.4 工单管理 ★

1. 进入 **工单管理**。
2. **创建工单**：关联设备 / 关联告警、填写问题、指派处理人、设置优先级。
3. **跟踪状态**：待处理 → 处理中 → 已完成。
4. **处理工单**：更新处理进度、上传记录、完结归档。

> 告警与工单可联动：告警中心一键派单即生成工单，形成"发现—派发—处置—闭环"的运维回路。

## 6. 常见问题

**Q1：登录后看不到任何数据 / 菜单很少？**
- 非超管：确认登录的账号所属租户是否正确，以及角色是否被授足权限（联系管理员在「用户管理 → 角色管理」追加权限）。
- 区域受限：操作员可能仅被授权部分区域（`AllowedAreaIds`），列表按区域白名单过滤，属正常。

**Q2：设备认领后没有数据？**
- 确认设备已在线（4G 信号正常）。
- 确认协议配置（**协议管理**）正确，设备品类判定无误。
- 确认设备已开始上报；部分设备数据为"命令拉取"模式（如水流量的 `getFlowInfo`），需在对应页面点"拉取实时流量"。

**Q3：能下发控制但点了没反应 / 按钮是灰的？**
- 灰色按钮=当前角色缺少对应**写权限**（如 `SEND_DEVICE_COMMANDS`）。联系管理员授权。
- 若按钮可点但无响应：检查设备在线状态与网络。

**Q4：想新增一种设备品类 / 协议？**
- 协议在**协议管理**中配置；新设备品类经由"认领"时的探测自动判定，无需手工建设备。

## 7. 附录：技术约定

- **API 前缀**：`/api/v1`；生产环境基地址为 `https://cloudiot.hbnewworld.com/api/v1`（前端构建时已内置）。
- **多租户隔离**：后端按 JWT 中的 `AppCode` 做行级数据过滤；超管不下发 `AppCode`，可跨租户。
- **设备数据链路**：安圣设备经 MQTT（AnSheng 协议）上报 → 平台采集服务 `DataCollectionService` 映射物理量（温度/湿度/电/水/气等）→ 落 `DeviceDataRecord`。水表字段 `waterflow / watertotal / wpulses` 即映射为 `WaterFlow / WaterTotal / WaterPulses`。
- **认领链路**：`POST /api/v1/ansheng/claim` → 探测 → 判品类 → 建档 → 转 Device。
- **文档维护**：本手册随功能迭代更新；如菜单/权限与线上不一致，以线上实际为准并反馈修订。
