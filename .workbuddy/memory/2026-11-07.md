## 租户登录日志不可见 — BugFix（+ 回归 + 真机复验）

### 现象
用户报：租户登录后「登录日志管理」看不到登录日志。

### 根因（双链路定位）
- 前端 `LogManagementPage` 是纯透传：请求不带租户标识、回包不做 appCode 过滤、菜单靠 `hasPermission('view_logs')` 控制（已不读静态 DEFAULT_ROLES，以服务端 `UserDto.permissions` 为准）。前端无 bug。
- 后端根因在**写入**：`AuthService.RecordLoginLogAsync` 没把已算好的 `effectiveAppCode` 传给 `LogRepository.LogLoginAsync`，后者构造 `LoginLog` 也不赋值 `AppCode` → 每条登录日志 `AppCode` 恒为 NULL；而 `GetLoginLogsQuery` 用 JWT 的 AppCode 做 `WHERE AppCode == 租户` → 租户查询永远 0 条。超管不签 AppCode claim + 过滤器短路 → 看全量（含 NULL 行），故「超管可见、租户不可见」。
- 次级缺口：staff/chef/operator/customer_admin/user 静态权限集（及为 null 的种子 Permissions）不含 `VIEW_LOGS`，被 `LogsController` 控制器级 `[PermissionAuthorize(VIEW_LOGS)]` 整组 403，连页面都进不去。

### 修复（P0 + P1）
- P0（寇豆码）：`ILogRepository.LogLoginAsync` / `LogRepository.LogLoginAsync` 加 `appCode` 参数并赋值 `LoginLog.AppCode`；`AuthService.RecordLoginLogAsync(user, success, appCode)` 透传，`LoginAsync:147` 调用处传 `effectiveAppCode`。新增迁移 `20261107023459_BackfillLoginLogAppCode`：`UPDATE login_logs SET AppCode=(SELECT u.AppCode FROM users u WHERE u.Id=login_logs.UserId) WHERE AppCode IS NULL;`（用真实表名）。
- P1（用户拍板「全部租户角色」）：`Configuration/RoleConfig.cs` 的 admin/operator/chef/staff/customer_admin/user 静态权限集均加入 `Permissions.VIEW_LOGS`；新增 `CUSTOMER_ADMIN`/`USER` 常量与 `GetCustomerAdminPermissions()`/`GetUserPermissions()`。

### 测试与验证
- 严过关：30 新用例全绿（20 单元 + 10 集成真实 MySQL）。覆盖 RoleConfig 全租户角色含 VIEW_LOGS、AppCode 落库(InMemory)、租户隔离、6 角色 `GET /logs/login`→200（修复前 403）、无 view_logs 自定义角色仍 403、超管看全量。
- 主理人独立核验：4 处改动真实落盘；真实库 `login_logs` 194 行、`AppCode IS NULL=0`、回填迁移已在 `__EFMigrationsHistory`（QA 重启进程时自动迁移已执行）。
- 真机：`direct-DLL + Staging` 重启（task jC6OeZ，:5000，hosting=Staging，自动迁移 no-op），MQTT 连真机/设备实时上报正常；超管登录→`GET /logs/login` code 200、返回带 appCode 字段的记录，超管自身日志 appCode=null（符合预期）。

## 权限清单数量漂移 — 根治

### 背景
QA 早前发现 `Permissions.All`(75) 与 `GetSuperAdminPermissions()`(70) 数量不一致（技术债）。根因：后两者是手写副本，新增常量未同步。

### 漂移精确差异
- `Roles.GetSuperAdminPermissions()`(70) 漏 5 项：`CREATE_AREAS`/`UPDATE_AREAS`/`DELETE_AREAS`/`MANAGE_GATEWAY_CONFIG`/`MANAGE_TUNNEL_CONFIG`。
- `PermissionService.GetAllPermissionCodes()`(70) 漏上述 5 项，且额外漏 3 项设备指令：`VIEW_DEVICE_COMMANDS`/`SEND_DEVICE_COMMANDS`/`CANCEL_DEVICE_COMMANDS`。
- `GetPermissionDescriptions()` 缺这 8 项描述。
- 运行时超管走 `GetEffectivePermissionsAsync` 短路返回 `All`(75) 自洽；但静态回退路径（GetRolePermissions/GetAllRolePermissions 字典）用 70 项副本 → 回退时超管/管理员缺这 5 权限。

### 修复（寇豆码 / software-engineer-4，最小侵入、未 commit）
- `Roles.GetSuperAdminPermissions()` 整体改为 `return Permissions.All;`（保留 `<summary>` 说明历史漏授）。
- `PermissionService.GetAllPermissionCodes()` 整体改为 `return Permissions.All;`。
- `GetPermissionDescriptions()` 补 8 条缺失描述（区域增改删 / 网关·隧道配置 / 设备指令 3 项）。
- `GetAdminPermissions()` 不变：仍先 `GetSuperAdminPermissions()` 再 `Remove` API 配置 → `admin ⊆ super_admin` 契约维持（现在 admin = All 去掉 API 配置）。
- 未改 `Permissions.All` 本身；未 commit。

### 验证
- 主理人独立核验：grep/Read 确认两方法体均为 `return Permissions.All;`、8 条描述已落盘；`Permissions.All` 常量数 = 75。
- 工程师编译 `dotnet build -o C:/temp/permfix` 0 错误；主理人独立复编 `dotnet build -o C:/temp/permfix_verify` 0 错误 0 警告。
- 工程师跑 RoleConfig/PermissionService 单测 21 通过 0 失败；无硬编码 `Count==70` 断言需改。

### 收益
静态回退路径下超管/租户管理员现在能正确拿到此前漏授的 5 个权限；`PermissionsController.GetAllPermissionCodes().Count` 与 `GetPermissionDescriptions()` 不再漏项（UI 不再出现空描述）。数量漂移技术债闭环。
