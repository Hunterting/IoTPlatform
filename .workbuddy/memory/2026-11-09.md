## IIS 前端页面 404 修复（SPA 由后端 ANCM 托管）
- 现象：`http://localhost:8088/index.html` → 404；IIS 应用池“无托管”(ANCM)，前端 dist 放发布根目录（物理路径直接含 index.html）。
- 根因：`Program.cs` 未启用静态文件服务（缺 `UseStaticFiles`/`UseDefaultFiles`/SPA fallback），后端只暴露 API，静态资源一律 404。与“纯 IIS 静态托管缺 Static Content 角色”是两回事。
- 修复：`Program.cs` 认证前加 `app.UseDefaultFiles()` + `app.UseStaticFiles(new StaticFileOptions{ FileProvider = new PhysicalFileProvider(app.Environment.ContentRootPath) })`；`MapControllers`/`MapHub` 之后加 `app.MapFallbackToFile("index.html", 同 FileProvider)` 支持 React Router 深链刷新（不拦截 /api）。
- 验证：`dotnet build -c Debug` EXIT=0。
- 部署待办：重新发布后端到发布根（FolderProfile→F:\Web\IotWeb），确认 dist 的 index.html+assets/ 在根；重启站点复测。未 commit。
- 安全提示：从 ContentRoot 提供静态文件会暴露 appsettings.json/DLL；可选改为只服务 wwwroot 子目录并改用默认 `UseStaticFiles()`。
- 前端用绝对 API 地址 `https://cloudiot.hbnewworld.com/api/v1`（2026-11-07 已定），后端 `UseCors("AllowAll")` 放行跨域，无需 /api 反向代理。

## 文件上传绝对路径问题修复
- 现象：`appsettings.json` 的 `FileStorage:UploadPath` 写死 `H:\IoTPlatform\uploads`；部署到服务器（无 H: 盘）后上传失败。
- 附带潜在 bug：上传用 `<UploadPath>/<relative>`，但 `DeleteAttachmentAsync` 与 `GetFilePhysicalPath` 只用 `FileUrl`(相对段) 拼 CWD 还原物理路径，导致下载 404、删除残留文件（开发机也复现）。
- 修复：`Services/FileStorageService.cs` 注入 `IWebHostEnvironment`，新增 `GetUploadRoot()`——绝对路径原样用、相对路径 `Path.Combine(ContentRootPath, x)` 解析；上传/删除/下载三处统一走 `GetUploadRoot()`。`appsettings.json` 改 `UploadPath: "uploads"`（开发机 ContentRoot=H:\IoTPlatform → 仍解析到 H:\IoTPlatform\uploads，存量文件不丢）。
- 验证：`dotnet build -c Debug` EXIT=0，0 错误（91 历史警告无关）。
- 待办：重新发布后端；未 commit。注意：SPA 静态文件现从 ContentRoot 提供，uploads/ 目录也会被 StaticFileMiddleware 直接 GET 到（绕开下载接口鉴权），属上一处 SPA 改动的连带暴露，待后续收紧（建议 uploads 移出 ContentRoot 或仅经接口下载）。

## 上传文件禁止匿名下载（收紧 SPA 静态托管）
- 需求：用户明确“不能匿名下载”上传文件。
- 根因：SPA 静态中间件从 ContentRoot 提供文件，`GET /uploads/...` 被匿名托管，绕开鉴权下载接口。
- 修复：
  - 新增 `Infrastructure/PrefixExcludingFileProvider.cs`：包装 IFileProvider，首个路径段命中 `uploads`（不区分大小写）时返回 NotFound，使该目录对静态托管不可见。
  - `Program.cs`：`UseStaticFiles` 改用 `PrefixExcludingFileProvider(contentRootProvider, "uploads")`；SPA 回退 `MapFallback` 改为自定义 handler，`/uploads/*` 直接 404，其余未匹配前端路由返回 index.html。
  - 效果：匿名 `GET /uploads/...` → 404；上传文件只能经 `AttachmentsController.Download` / `ContractsController.DownloadContract`（带鉴权）的 `GetFilePhysicalPath` 读取（物理路径仍由 `GetUploadRoot()` 解析到 ContentRoot/uploads）。
- 验证：`dotnet build -c Debug` EXIT=0，0 错误。未 commit。
