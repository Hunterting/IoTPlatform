## 多租户授权模型改造 + M09 工作台 UI（标准 SOP 全链路交付，6 commit 未 push）

### 需求来源
用户要改造工作台截图：左列删变频排风/预警事件铺满、右列分客户列表+区域管理、中列环境监测→设备情况、点区域看设备；三角色权限：超管全客户/admin 授权批次/下级单客户。

### 关键发现：代码原本不支持「一个 admin 管多客户」
- `users` 表只有单 `CustomerId`/`AppCode`，JWT 只签单 claim；无中间表/多值字段
- 「admin 有很多客户」是假象：`CustomersController.IsAdminLike()` 把 admin 当超管、后端返回全部客户，前端 `DashboardPage.visibleCustomers` 又砍回 1 条
- 用户拍板：**多对多授权**（同一客户可给多个 admin）、**admin 自身单值留空**、下级仍单客户零回归、**先做模型改造 UI 随后**

### 架构决策（设计文档 .workbuddy/design/multi-customer-auth-*.md）
- 授权存储：`user_customers` 中间表（唯一约束 `(UserId,CustomerId)` + 审计列），不用逗号串
- **claim 是快照、DB 是权威**：JWT 签 `ManagedCustomerIds`（上限 50），但每次请求经 `ICustomerScopeService` 读 DB → 超管改授权旧 token 下次请求即生效，无需吊销
- 三分支：`All`（超管，空集合=不过滤）/ `Multi`（admin，读 DB 集合）/ `Single`（下级，零授权表访问）
- admin 不带单 CustomerId/AppCode claim；下级逐字段不变
- 越权判定全在业务层显式过滤，全局过滤器（超管/空 AppCode 不装 + 启动期冻结）不 when 防线

### 关键经验（铁律级）
- **守卫实体必须与实际落库表一致**：命令记录守卫点查 DeviceCommand（0行）而真数据在 anshengcommandrecords → 查不到 return true 恒放行。这类"守卫实体错配"全局排查过，仅此一处。
- **共享行判据读写必须分离**：放宽写侧 IsSharedSystemRow 认 "system" 会让 device/gateway/tunnel 的 system 行绕过写校验；新增读侧专用 IsSharedReadRow。
