## 缺陷一（P0，联调阻断）：协议配置 ProtocolType/IsActive 未写入
**现象**：经 API 创建的安圣协议配置永远认领失败 `AdapterUnavailable`。
**根因**：`Services/ProtocolConfigService.cs` 创建路径不写 `ProtocolType`（NULL）、不设 `IsActive`；`StartProtocolAsync` 只改 `Status` 不同步 `IsActive`。而消费方（`AnShengDiscoveryService` 扫描 + `ResolveProtocolConfigIdAsync`）按 `IsActive && ProtocolType == "ANSHENG_MQTT"` 筛选 → 永远筛不到。
**修复**（工程师寇豆码，唯一改动文件 `ProtocolConfigService.cs`，+145 行）：
```csharp
public static string? DeriveProtocolType(string? type)
    => string.IsNullOrWhiteSpace(type) ? null : type.ToUpperInvariant();
private static bool IsRunningStatus(string? status)
    => string.Equals(status, "active", StringComparison.OrdinalIgnoreCase);
private static bool ReconcileDerivedFields(ProtocolConfig config) { /* 幂等补齐 ProtocolType + IsActive */ }
```
- Create 补 `ProtocolType = DeriveProtocolType(request.Type)` + 显式 `IsActive = false`
- Update 用 `ReconcileDerivedFields` 取代 `config.IsActive = request.IsActive`（防前端回填复发）
- Start/Stop 在 Status 短路前插幂等补齐 → **存量脏数据会在下次 start/stop/update 自愈**

**关键事实纠正**：`Models/ProtocolConfig.cs:21` 的 `IsActive` 默认是 `= true`（不是 false）。`CreateProtocolConfigRequest` **无 ProtocolType 字段**，所以修复方向是后端从 `Type` 派生，不动前端契约。
