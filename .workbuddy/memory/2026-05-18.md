# 2026-05-18 工作记录

## 数据采集模块架构分析
- 对 IoTPlatform 数据采集模块进行了全面代码审查（Models/Services/Controllers/Infrastructure/Protocol 全链路）
- 发现核心问题：
  1. **DeviceDataRecord 缺水/电/气专用字段** — 只有环境监测字段（温湿度/PM2.5/CO2等），无 WaterFlow/ElectricKWh/GasFlow 等
  2. **DataCollectionService 不解析 SensorData JSON** — 原始 JSON 直接存库，DeviceSensor.LastValue 从不更新，所有物理量字段为 null
  3. **MQTT 配置键名不匹配** — appsettings.json 用 `MQTT.Server` 但代码读 `Mqtt:Broker`
  4. **协议适配器层未接入主链路** — Modbus TCP/RTU、OPC UA 适配器存在但与 MqttClientService 是两套并行系统
  5. **EnergyTypes 仅元数据** — 不驱动任何采集行为或解析策略
- 结论：MQTT+JSON 通用数据能收能存(raw)，但缺少水/电/气的结构化解析存储能力
- 提出改造优先级：P0(修复JSON解析+配置键+更新LastValue) → P1(新增能耗字段) → P2(集成协议层+时序DB)
