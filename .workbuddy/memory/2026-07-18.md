## Bug 修复：设备能耗类型传输不正确

### 问题
设备管理添加和编辑时，能耗类型（energyTypes）传输不正确。

### 根因
- **后端** `DeviceService.NormalizeEnergyTypesJson` 将 EnergyTypes 存储为 JSON 数组字符串：`["electric","water"]`（MySQL json 列类型要求）
- **前端** `deviceAdapter.ts:adaptDeviceDtoToDeviceItem` 使用 `.split(',')` 解析，将 `["electric","water"]` 拆成 `['["electric"', '"water"]']` — 带括号和引号的乱码
- 导致编辑设备时复选框全部失配，无法正确显示已保存的能耗类型

### 修复
- **文件**：`Web/src/app/services/adapters/deviceAdapter.ts`
- **修改函数**：`adaptDeviceDtoToDeviceItem`
- **修复内容**：将 `.split(',')` 替换为 `JSON.parse()` 优先解析，catch 时降级为逗号分隔解析（兼容旧数据）

### 验证
- 前端 Vite 构建通过 ✅
- 后端无需改动（发送方向 `energyType.join(',')` → 后端 `NormalizeEnergyTypesJson` 转换为 JSON 数组，链路正常）

## Bug 修复：设备管理表单 input null value 警告

### 问题
React Warning: `value` prop on `input` should not be null. 设备添加时出现控制台警告。

### 根因
`DevicesPage.tsx` 的 `DeviceFormModal` 初始化时 `installDate`/`warrantyDate` 为 `null`，`serialNumber`/`category`/`voltage`/`supplier`/`power` 缺少 `|| ''` 防护，导致 React 受控组件的 value 可能为 null。

### 修复
- **文件**：`Web/src/app/pages/DevicesPage.tsx`
- **修改内容**：8 处 input 的 `value={formData.xxx}` 添加 `|| ''` 防护（power 用 `?? ''`）
  - `serialNumber`(L618), `category`(L630), `installDate`(L686), `power`(L726), `voltage`(L739), `supplier`(L769), `warrantyDate`(L782)

### 验证
- 前端 Vite 构建通过 ✅（`✓ built in 11.28s`）
