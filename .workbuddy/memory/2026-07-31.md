### 核实现场后修正的两处判断

**① B6（topic 不匹配）风险等级下调 —— 配置层面已经是对的**

`appsettings.json` 的 `AnShengMqtt` 节实际值：
```
PublishTopicPattern:    "/iot/server/iot-board/+"
WillTopicPattern:       "/iot/server/iot-board/+"      ← 与 Publish 完全相同
SubscribeTopicTemplate: "/iot/client/iot-board/{imei}"
```
与现网一致。`AnShengMqttProtocolOptions.cs:36/39/42` 里的 `/devtoser/*` 只是过时 fallback 默认值，被配置覆盖。
→ **T12 的多组 topic 共存可延后**，不必提前到 Phase 1。
→ 平台占位符约定是 `{imei}`（非协议的 `%imei%`），`Replace("{imei}", serialNumber)` 工作正常。

**② B4 的实际影响比文档描述更严重 —— 离线检测从上线起就没工作过**

因 `WillTopicPattern == PublishTopicPattern`，而 `AnShengMqttProtocolAdapter.cs:294` 判定条件为
`topic.StartsWith("/devtoser/will")` → **永远为 false**。
结论：安圣设备掉线平台永远感知不到（好在也不会把正常上报误判为离线）。
附带隐患：两个 Pattern 相同 → Adapter 对同一 topic 订阅两次。
