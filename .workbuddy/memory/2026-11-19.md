## ⚠️ 铁律级 bug：萤石取流验证码参数名写错 ewcode→code
- 现象：加密摄像头填了验证码 DLIHRV、数据库 cameras.EncryptionCode 字段已在，仍报 60019。
- 根因：11-14 首次修复时把验证码参数写成 `form["ewcode"]`，但萤石官方文档 `docs/萤石开放平台_API_云接入_OPEN_API.docx`「9. 获取播放地址」`/api/lapp/v2/live/address/get` 参数表明确规定参数名是 **`code`**（描述"ezopen协议地址的设备的视频加密密码"），全文 ewcode 出现 0 次。萤石忽略未知参数 ewcode → 验证码没送达 → 依旧 60019。当时只静态编译未查文档/未真机，故漏掉。
- 修复（`Services/EzvizService.cs`，唯一文件）：
  - `:362` `form["ewcode"]` → `form["code"]`（附文档依据注释）。
  - `:536` BindCameraAsync `existing.EncryptionCode = request.EwCode` 改条件覆盖 `if(!IsNullOrWhiteSpace(request.EwCode))`，防重绑定留空时清空已存验证码。
- 独立 QA NoOne：docx 原文核实参数名 code；实测 `ewcode`→`EwCode` JSON 大小写映射 OK、LIKE 按 serial 找回 camera OK、DLIHRV 能送达 form["code"]；编译 0 错误。
- ⚠️ 运行时 bug：静态只能证明代码正确，**必须重建后端 DLL + 重启 :5000 才生效**（前端无关）。真机若仍 60019：查 HLS(protocol=2) 下萤石是否接受 code、DB EncryptionCode 是否=D L I H R V、绑定行 StreamUrl 是否 `ezviz:{serial}:1`。
- 教训：调第三方 API 参数名必须逐字核对官方文档，不能凭记忆；加密取流这类只有真机能暴露的 bug，静态 QA 有盲区。

## 删除设备报 405（IIS WebDAV，服务器配置而非代码）
- 用户部署后删除设备报 IIS 405 黄页 "HTTP verb used to access this page is not allowed"，弹窗显示"服务器错误请稍后重试"。
- 路径核对无误：前端 `deviceApi.ts:110` `DELETE /devices/{id}`，后端 `DevicesController.cs:196 [HttpDelete("{id}")]`。
- 405 是 IIS 层返回（非应用返回），典型 WebDAVModule 拦截 DELETE/PUT。生产 IIS 站点 `C:\IotCloud`。
- 解决：在服务器 web.config 的 `<system.webServer>` 加 `<remove name="WebDAVModule" />`（modules 段）与 `<remove name="WebDAV" />`（handlers 段），或在 IIS 管理器卸载 WebDAV 角色/对站点禁用 WebDAV。改完回收应用池。非代码改动，无需重新发布后端。
- 关联：PUT/上传等同源动词可能也被拦，一并解决。
