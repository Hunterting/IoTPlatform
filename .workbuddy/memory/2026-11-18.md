## 区域管理删除/修改报 400（page=[object Object]）BugFix
- 用户报错：`400 errors.page: "The value '[object Object]' is not valid."`。
- 根因：`Web/src/app/pages/AreaManagementPage.tsx:590` 全局错误条的「重试」按钮写成 `onClick={refreshAreas}`。`refreshAreas(page?, pageSize?, filters?)` 是带参函数，React onClick 把 MouseEvent 塞进 page → `getAreas(page=Event)` → axios params.page 序列化成 `[object Object]` → 后端 `AreasController.GetAreas([FromQuery] int page)` 绑定失败 400。错误条只在 error 非空时出现，故用户删/改失败看到重试按钮、点它触发 400，误以为"删除修改报错"。删除/修改本身（PUT/DELETE + loadAreaTree）不带 page，无独立根因。
- 修复：`onClick={() => { refreshAreas(); refreshAreaTree(); }}`——箭头函数无参调用，顺带刷新树。单文件改动。
- 独立 QA 5/5 通过、路由 NoOne：根因链核实成立、无第二同类 bug（全前端 onX={带参函数} 扫描）、编译 0 错误。
- ⚠️ 铁律级教训：**React 事件处理器禁止直接挂带参函数**（`onClick={fnWithParams}`）——事件对象会成为第一个实参。分页加载函数 `loadXxx(page)` / `refreshXxx(page)` 尤其易踩，必须 `onClick={() => loadXxx()}` 包装。
- QA 非阻断建议（未做）：修复处两个未 await 的 Promise 并发有竞态，可改 `await Promise.all([refreshAreas(), refreshAreaTree()])`。
- 未 commit；本次纯前端改动，若要上线需重新打包前端 zip。

### 排查结论（用户回传测试结果）
- nanomq 配置：auth 段 `allow_anonymous=false`/`no_match=deny`/`deny_action=ignore`，但 `acl={include...}` 被注释（无 ACL 规则文件）。
- 用户测试：nanomq_cli sub `/iot/server/iot-board/#` 和 `+` 都连上（connect result 0），但都收不到设备报文；手动 pub `hello` 到 `/iot/server/iot-board/862288087444798` 后，sub 窗口**成功收到 hello**。
- 结论：**broker/订阅/ACL/topic 全部正常**。真相=设备在 16:55:18 发过一次 `method:connected` 后停止上报（设备侧不发）。历史日志里每 30s 上报的是另一台设备 IMEI 863434084755211，行为不同。
- 最后待验证：平台订的是 `+`（单层），测试用的是 `#`（多层）——设备 topic 是单层 `+` 应匹配，但需用 nanomq_cli sub `+` + 手动 pub hello 再确认一次，彻底排除 `+` 通配符问题。若 `+` 也能收到 hello → 板上钉钉是设备不发，需查设备侧（重启设备/检查设备固件上报逻辑/确认设备连的 broker 地址）。
- 另注：用户 sub 测试曾出现 `disconnected reason:139`(Session taken over)——sub/pub 用相同默认 ClientID 互踢，多窗口测试须加 `-i` 区分 clientid。
- 用户用 PowerShell 发有效报文 `{"imei":"...","method":"connected"}`（注意变量 $msg 须先定义再 pub），平台日志仍无"上行到达"。
- 🔴🔴 **确定代码缺陷（本次根因）**：`AnShengMqttProtocolAdapter` 断线重连后订阅丢失。因果链：
  - `OnDisconnectedAsync`:749 只打日志+触发重连，**未重置 `_isCollecting=false`**。
  - `ConnectAsync`:218 每次 `new MqttClient()` 重建客户端 → 新客户端订阅表为空。
  - `ReconnectLoopAsync`:797 重连成功后调 `StartDataCollectionAsync` 试图重订阅，但该方法 :287 `if(_isCollecting) return` 直接跳过（因为 _isCollecting 一直是 true）→ **订阅永远不恢复**。
  - 触发条件与用户 17:28 重启 nanomq 导致平台断线重连的时间线完全吻合。
  - 修复方向：`OnDisconnectedAsync` 里置 `_isCollecting=false`（或在 `ConnectAsync` 重建 client 后重置）；确保重连后能重新订阅。另 `SubscribeTopicAsync`:374 未检查 SUBACK ReasonCode（可观测性改进）。
